# Public security API contract

GET/HEAD /security/api/summary returns application/json, no-store. This is a public, sanitized, read-only projection of fixed local state, not raw evidence. No query parameters, mutation verbs, scan controls, resolve/acknowledge controls, source/file selection or private report routes. Unsupported method: 405; unknown/traversal/query path: 404; foreign Origin: 403; unavailable/corrupt/oversized state: 503, not zero findings.

The frontend is owned by dev-ui during the redesign; Builder owns src and backend tests. Main owns combined publication. Frontend asset locations currently allowlisted by src/handler.mjs: /security/ -> public/index.html, /security/styles.css -> public/styles.css, /security/app-20261028.js -> public/app.js (and legacy /security/app.js alias). Preserve the versioned script URL: the legacy URL has a cached prepublication 404 at Cloudflare. Additional asset routes require main/backend coordination; do not infer a wildcard filesystem route.

## JSON v1

- schemaVersion: 1; generatedAt: response time, NOT scan time.
- scope: repository, components, runtime, reviewed branch or restricted-name notice, commit (40-hex or null), dirty (boolean/null), sourceCoverage, testScope. All display text is reviewed; raw branch labels are not published.
- scheduling: schemaVersion=1; status="unknown"|"stale"|"enabled"|"disabled", enabled boolean/null, lastKnownEnabled boolean/null, agent="dev-security", verifiedAt ISO/null, nextRunAt ISO/null, cadence/evidenceSource/message reviewed strings/null. Private metadata requires a UUID jobId and scope="security-dashboard"; job identity is not published. Reads only separately supplied verified scheduler.json metadata (see RUNBOOK.md), never ledger or calculated cron projections. Missing/malformed/future evidence is unknown; >24h is stale, enabled=null and nextRunAt=null. Current valid evidence publishes the observed enabled state; nextRunAt is included only if scheduler-supplied and still future.
- run: null until a scan exists, else id, startedAt, finishedAt, status="complete"|"degraded", mode="full". Complete requires every expected scanner to succeed and all rubric dimensions to be measured. Recency comes from finishedAt; a fresh response does not make an old run fresh.
- scannerManifest: version="1.0.0", expectedCount/reportedCount/completedCount/missingCount (source inventory counts, no paths), sources with exact source/category membership for four dependency app scopes and secrets/sast/configuration/tests/coverage/monitoring. Missing records are projected as unavailable with null counts and make the run degraded; a category earns weight only when every expected source in that category succeeds. Duplicate, unknown, miscategorized or unsupported-status scanner records are malformed state (HTTP 503), not a clean snapshot.
- score: value 0–100, confidence 0–100 (available rubric weight, not statistical probability), freshness="unknown"|"fresh"|"stale"|"expired", ageHours number/null, dimensions keyed by sast/dependencies/secrets/configuration/coverage/tests with weight/value/contribution, rubric with version/weights/penalties. Unknown dimension value is null and contributes zero.
- counts: critical/high/medium/low/info active report counts, including accepted-risk but excluding resolved. These are overall incidents, not only code CVEs.
- scans: source, category, status="ok"|"failed"|"unavailable", findingCount number/null, durationMs number/null, completedAt, severityCounts (critical/high/medium/low/info or null when incomplete). Sources: dependencies:game/usage/architecture/security, secrets, sast, configuration, tests, coverage, monitoring. A failed scan's count is N/A, never an assumed zero. Monitoring inventory may complete while a constituent scanner fails.
- metrics.coverage: null when its scanner is missing/failed; otherwise lines/branches/functions percentages (number/null), statements=null, source. These measure security-dashboard/src only, not the game/repository or security-test coverage.
- metrics.tests: null when its scanner is missing/failed; otherwise passed/failed/skipped counts and passPercent number/null. Pass denominator excludes skips.
- metrics.sast: ruleCount (10), scannedFiles number/null, parseOrScanErrors number/null. initialParseErrors and compatibilityRepairedFiles are measured counts/null. Original partial parsing stays failed/degraded unless an AST-verified same-rule second pass completes on every affected file; original errors/proof remain private. No errors are ignored or source files excluded for score.
- metrics.secrets: scannedFiles/scannedBytes number/null for the bounded text scope.
- metrics.dependencies: knownCVEs=null and reviewed source explanation. npm advisory findings are in scans/incidents; do not relabel advisory totals as CVE totals.
- metrics.connector: null or installed/running versions, vendorMinimum, reviewed source. The minimum is specific to the October certificate-trust incident, not a live latest-release/advisory claim.
- incidents: reports with id (opaque hash), kind, reviewed title/remediation, severity, status="open"|"resolved"|"accepted-risk", confidence="high"|"medium"|"low", reviewed component, source, firstSeen/lastSeen/resolvedAt, lastRunId, observationCount, verification, cvss number/null (only actual vendor advisory score, never derived from our score), cwe list of actual supplied CWE IDs, history list {event,at,runId}. Kind currently dependency/secret/sast/configuration/monitoring/history. Runtime informational observations are reports too; informational does not mean a failed check. Historical resolved connector remediation must not be presented as a new active vulnerability.
- limits: reviewed disclosure strings.

Incident reconciliation records one observation per run ID and fingerprint. Replaying an ingested run ID is a no-op; a later run adds one observation. Conflicting within-run duplicates retain the highest severity, with the first payload winning equal-severity ties; they do not create duplicate lifecycle events.

Never turn null into zero/100, call degraded clean, hide unknown/stale scheduling, or claim a measured percentage without scope. Render scanner-authored/private content only through this public contract; do not request a raw evidence endpoint. Every report is expandable/searchable by its safe metadata; detailed source evidence remains operator-local.

SAST matching policy: inline suppression directives are disabled in both passes. Compatibility views map UTF-8 offsets and columns back to original source before exact rule/path/span deduplication. Multiple same-line findings remain separate occurrences and have occurrence-aware incident keys.
