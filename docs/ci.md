# Continuous integration

The workflow in `.github/workflows/ci.yml` runs on pushes to `main` and pull requests. The game job checks only `game/`; `usage-dashboard/` and other repository projects are outside this job’s scope. It uses Node 22, installs game dependencies from `game/package-lock.json`, runs the existing game tests, and prints Node’s coverage summary.

Game checks include locked installs, npm audit (fail at high or critical advisories), syntax checks over all game source JS/MJS files, and the locked Biome 2.6.6 toolchain under `.github/ci-tools/` (rules: unreachable code, debugger statements, constant conditions, duplicate object keys). Both npm dependency graphs are installed with `npm ci` and audited. The Gitleaks CLI is pinned to v8.30.1 and its Linux x64 archive is verified against the SHA-256 published in the upstream release checksums manifest before use. The secrets job fetches full git history and scans every reachable ref/commit; it does not call the paginated/unpaginated GitHub PR-commits API.

Coverage is informational only: it is printed in the Actions log, with no threshold or uploaded artifact. The candidate was tested with Node v22.23.4: 173 tests (162 passed, 11 skipped, 0 failed), with 74.85% lines, 85.88% branches, and 40.32% functions across all included files. The 11 skipped tests are browser/native-audio checks requiring browser/audio runtime support; the numbers are not browser-runtime coverage and include client and vendored modules.

The workflow uses ordinary `pull_request`, grants only `contents: read`, sets job timeouts, and disables checkout credential persistence. It requires no repo secrets and makes no write calls. Third-party GitHub Actions are pinned to full commit SHAs verified against upstream tags: checkout v4.2.2 (`11bd71901bbe5b1630ceea73d27597364c9af683`) and setup-node v4.4.0 (`49933ea5288caeca8642d1e84afbd3f7d6820020`).
